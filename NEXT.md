## What this is

`babysit-sh` — an agent-agnostic supervisor for long-running agent tasks. An
external supervisor process starts fresh worker sessions one after another until
the task is done, the budget runs out, or a human stops it. It is the inverse of
`../agent-loop` (there the agent hands off to itself; here the supervisor owns
succession, so a worker cannot break the chain).

Since session 2 there is a second, human-facing surface: one sentence to an
agent ("I want to use babysit on this project: <repo URL>") installs the driver
**and registers the convention in the project's `AGENTS.md`** (plus a
`CLAUDE.md` importing it). After that the human only says **"Using babysit,
<goal>"** and any agent session knows to write `.babysit/tasks/main/TASK.md` and
start the supervisor. The block is generated by `babysit.sh agents-md`
(idempotent, `--check` for CI).

Since session 3 the layout is multi-task **by default**: one `.babysit/`
directory per project holds the driver plus a `tasks/` registry, and each task
keeps its state in `.babysit/tasks/<name>/` with its own supervisor. The default
task is `main`; `--task NAME` selects another one on every subcommand;
`babysit.sh ls` lists them. An older flat install (`TASK.md` directly in
`.babysit/`) is still detected and used as-is.

## Decisions already made — keep them

- **The supervisor starts sessions, the worker never does.** Do not add an
  "agent hands off" mode.
- **Time-based budget, not turn-based.** `budget` reports remaining seconds and
  `DECISION=handoff-now` near the deadline.
- **Progress is `STATE.md` hashing** → stall; **exit code** → failure; both halt
  loudly with a reason in `HALTED`. Do not make "no state change" silently retry.
- **One `.babysit` directory per project; one task directory and one supervisor
  process per task.** Tasks live in `.babysit/tasks/<name>/`; `--task` (global,
  pre-parsed before dispatch) selects one, default `main`. A flat `.babysit/`
  holding `TASK.md` is the legacy single-task layout and is still honoured.
  `--dir` is the raw escape hatch. `agents-md` targets the *project*
  (`--project`/`BABYSIT_PROJECT`) because `AGENTS.md` lives at the project root.
- **The filesystem is the task registry.** Do not add a central `$HOME/.babysit`
  index; `tasks/<name>/` plus `babysit.sh ls` is enough.
- **`AGENTS.md` is the single source for the convention; `CLAUDE.md` only
  imports it** (`@AGENTS.md`), because Claude Code does not read `AGENTS.md`
  natively. Do not put `@` imports inside `AGENTS.md` itself (other tools treat
  them as literal text).
- **Managed blocks, not free-form edits.** Never rewrite the parts of
  `AGENTS.md` the user wrote; strip and re-append only the marked block.
- **Everything overridable by env**, because CI and tests depend on it.
- Worker sessions get `setsid` and have `PI_SESSION_FILE`/`PI_SESSION_ID` unset.

## Known gaps / things to fix

- No `TERM`/`INT` trap (item 1). `HALTED`/`DONE` get no final logline when the
  supervisor is killed directly.
- `install.sh` treats a missing `babysit.md` at the ref as fatal. Consider
  warning instead, or download the prompt after `init` succeeds.
- `once` ignores existing `DONE`/`stop` markers — it always runs one session.
  Decide and document (arguably it should refuse like `run` does).
- `agents-md` creates `CLAUDE.md` by default. It is documented and skippable
  (`--no-claude`), but watch for projects that would rather not have it.
- `supervisor_pid` trusts `kill -0` only (PID reuse) — same trade as agent-loop.
- No test asserts the *worker prompt actually reaches the CLI*; tests use
  `BABYSIT_CMD` without `@@PROMPT@@`. Consider a check with
  `BABYSIT_CMD='cat @@PROMPT_FILE@@'` asserting the contract text lands in the log.
